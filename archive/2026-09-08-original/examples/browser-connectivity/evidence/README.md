# Evidence guidance: browser connectivity case

No evidence file is included in this starter example. Evidence must come from work the participant actually performed.

Useful sanitized evidence could include:

- a small decision table showing adapter, addressing, reachability, DNS, proxy, and browser results;
- selected command output with prompts, addresses, adapter identifiers, and hostnames removed;
- a cropped proxy-settings comparison using fictional values;
- a simple troubleshooting flow diagram created by the participant; or
- a verification checklist showing that more than one approved destination loaded.

Evidence review must confirm that:

- no real address, network name, domain, username, path, or browser history is visible;
- no unrelated tabs, bookmarks, notifications, extensions, or account icons are visible;
- command output is shortened to the lines needed to support the claim;
- the evidence distinguishes observed results from reconstructed explanation; and
- the instructor's hidden method for staging the condition isn't included.
